# 《A股沪深主板短线交易系统》v0.6 规则冲突修订方案

> 本文档基于扣子出具的《开发前规则审查报告》（20项问题），对交易规则 v0.5 与软件开发规格书 v0.5 中的冲突逐项给出**可直接程序化**的解决方案。建议将本文档作为"v0.6补丁"整体提交给扣子，替代原有的模糊表述，再进入开发阶段。

---

## 〇、核心设计变更说明（先读这一段）

审查报告里的 A1（保守原则未实现）、A3（风险拦截不完整）、B2（风险阈值无映射）三个问题，**本质上是同一个问题**：市场环境、情绪灯号、单笔风险阈值、开仓权限，这四件事目前是四套互相独立的规则，程序没法知道该听谁的。

解决方式是建一张**统一状态分级表**，把"市场环境等级"和"情绪灯号等级"合并成一个"最终交易等级"，所有下游规则（风险阈值、是否允许开仓、仓位折扣）都从这一张表读取，不再各算各的。这是本方案的核心，后面所有条款都基于它展开。

---

## 一、高优先级问题修订方案（开发前必须解决）

### A1 + B2（合并解决）：状态调和模块 + 风险阈值映射表

**新增规则：市场环境×情绪灯号 → 最终交易等级**

| 情绪灯号 \ 市场环境 | A级（进攻） | B级（震荡） | C级（防守） |
| --- | --- | --- | --- |
| 绿灯 | L3 积极 | L2 谨慎 | L1 防守 |
| 黄灯 | L2 谨慎 | L2 谨慎 | L1 防守 |
| 橙灯 | L1 防守 | L1 防守 | L0 停止 |
| 红灯 | L0 停止 | L0 停止 | L0 停止 |

**取值原则：取市场环境等级与情绪灯号等级中较低（更保守）的一档**，与交易规则v0.5第3.3节"保守原则"完全一致。

**各等级对应的具体执行参数（同时解决B2的阈值映射缺失）：**

| 最终等级 | 单笔风险阈值 | 新开仓权限 | 仓位系数 | 可执行的交易模式 |
| --- | --- | --- | --- | --- |
| L3 积极 | 0.8%–1.0% | 允许 | 100% | 强势跟随 / 分歧低吸 / 弱转强 |
| L2 谨慎 | 0.5%–0.8% | 允许，仅限核心池 | 70% | 分歧低吸 / 弱转强（不追高） |
| L1 防守 | ≤0.3% | 原则上禁止，需人工在系统内填写理由后特批（单条记录，进is_violation字段） | 40% | 仅HOLD / REDUCE，不生成新BUY候选 |
| L0 停止 | 0% | 禁止（系统硬拦截，无特批入口） | 0% | 仅EXIT / REDUCE |

程序实现：
```
最终等级 = min(市场环境等级映射值, 情绪灯号等级映射值)
```
首页顶部同时展示两个原始状态和调和后的最终等级，避免用户看到"进攻+橙灯"却不知道最终按哪个执行。

### A2 + B7（合并解决）：统一状态数量为6种

两份文件、以及交易规则内部第10.6节与第14.5节，统一改为 **"六选一"**：

`观察 / BUY候选 / HOLD / REDUCE / EXIT / NO DATA`

补充"观察"状态的精确定义（原文件缺失，程序需要明确区分"观察"与"NO DATA"）：

- **观察**：数据完整、可信度达标，但前置条件（市场环境/情绪灯号/主线）未通过风险闸门检查链条，因此不进入个股买点分析。属于"条件不允许"。
- **NO DATA**：关键数据缺失或不可信，无法计算风险，因此无法给出任何判断。属于"数据不允许"。

两者UI展示需有明显区分（观察=灰色信息提示，NO DATA=红色警示+缺失字段清单）。

### A3：风险拦截条件补全为8条

软件规格书第4.3节"风险拦截"扩充为：

| 序号 | 拦截条件 | 触发来源 |
| --- | --- | --- |
| 1 | 账户风险超过单笔阈值上限 | 见上方等级表 |
| 2 | 没有止损价格 | 买点四要素检查 |
| 3 | T+1风险无法评估（可卖数量/持仓时间数据缺失） | 交易制度校验模块 |
| 4 | 关键数据缺失（现价/账户资金/止损价） | 数据管理模块 |
| 5 | 连续亏损保护触发（建议：连续3笔亏损减仓50%，连续5笔亏损当日停止新开仓） | 交易记录统计 |
| 6 | 当日累计风险 ≥ 2% | 见公式 B6 |
| 7 | 最终交易等级 = L0（红灯，或C级+橙灯组合） | 状态调和模块 |
| 8 | 最终交易等级 = L1 且未完成人工特批理由填写 | 状态调和模块 |

以上8条中，1/2/3/4/6/7为**系统硬拦截**（不生成BUY候选，无UI层面的例外入口）；5/8允许人工在明确记录理由后继续，理由文本写入交易记录表`is_violation`字段，用于后续复盘统计"违规交易"胜率，倒逼纪律。

### A4：交易记录表结构扩充

`trade` 表在原有字段基础上增加：

```sql
trade_mode          VARCHAR   -- 交易模式：强势跟随/分歧低吸/弱转强
theme                VARCHAR   -- 所属主线
market_env           VARCHAR   -- 买入时市场环境（A/B/C）
emotion_cycle        VARCHAR   -- 买入时情绪周期（六阶段）
emotion_light        VARCHAR   -- 买入时情绪灯号
final_level          VARCHAR   -- 买入时最终交易等级（L0-L3）
buy_reason           TEXT      -- 买入逻辑（对应买点四要素-1）
buy_position_note    TEXT      -- 买入位置说明（对应买点四要素-2）
risk_note            TEXT      -- 风险位置/止损理由（对应买点四要素-3）
exit_plan            TEXT      -- 退出计划（对应买点四要素-4）
sell_reason          TEXT      -- 卖出理由
avg_cost             DECIMAL   -- 平均成本（多次加仓后自动计算）
add_records          JSON      -- 加仓记录 [{time, price, qty}]
reduce_records        JSON      -- 减仓记录 [{time, price, qty, reason}]
is_violation         BOOLEAN   -- 是否违反系统建议开仓（对应拦截条件5/8的人工特批）
violation_reason     TEXT      -- 违规理由（特批时必填）
decision_score       INT       -- 决策质量评分（见B8）
stock_role           VARCHAR   -- 龙头/核心/跟风
```

一笔交易（trade_id）在加仓、减仓、分批卖出过程中始终保持同一ID，`add_records`/`reduce_records`记录完整轨迹，`avg_cost`随加仓自动重算，直到`可卖数量=0`时该trade状态转为`closed`。

### B1：主线评分体系——拆分而非删除龙头因素

**问题根源**：v0.5把"龙头强度"(30分)直接砍掉换成"市场认可度"(25分)，但市场认可度的评分依据（热度排名、涨停数量、龙头表现）里又包含了涨停数量，与"板块扩散"25分重复计算。

**修订方案**：三个维度重新拆干净，每个维度对应**不重叠**的数据来源：

| 项目 | 分值 | 维度定义 | 数据来源（不重叠） |
| --- | --- | --- | --- |
| 资金强度 | 25 | 资金是否持续进入该方向 | 板块成交额变化、资金净流入 |
| 板块扩散 | 20 | 个股数量层面的广度扩散 | 涨停数量、首板数量、连板数量、跟风股数量 |
| 政策/事件级别 | 15 | 逻辑级别 | AI辅助+人工确认 |
| 持续性/预期 | 10 | 能否持续 | AI辅助+人工确认 |
| 市场认可度 | 15 | 情绪/关注度层面的深度 | 热度排名、市场讨论度（非数量类，AI辅助） |
| **龙头表现** | **15（新增）** | 核心资金旗手强弱，主线的"发动机"指标 | 龙头股当日涨跌幅、量能、封板强度、连板高度变化率（自动计算） |
| 合计 | 100 | | |

这样处理的理由：龙头因素没有消失，而是从"笼统的30分"变成"可自动计算的独立15分"，同时避免和板块扩散的数量类指标重复。三个原本容易混淆的概念也各自有了清晰边界：**板块扩散=广度，市场认可度=热度，龙头表现=引领强度**。

## 二、中优先级问题修订方案（建议开发前解决）

### A5：数据管理模块（补入软件规格书）

在软件规格书新增"第二层-补充：数据管理模块"，实现交易规则v0.5第十一章：

- 每条数据字段附带三属性：`source`（行情接口/AI分析/人工输入）、`fetch_time`、`valid_until`
- 数据状态四分类：`valid`（有效）/ `expired`（过期，标记但可参考）/ `missing`（缺失，降低可信度）/ `invalid`（无效，禁止入库）
- 数据可信度评分公式：
```
数据可信度 = 行情完整度×0.4 + 更新时效性×0.3 + 来源可靠性×0.3   （100分制）
```
低于阈值（建议70分）自动进入"谨慎模式"，UI提示，不禁止查看但禁止生成BUY候选。

### A6：股票过滤模块

在数据采集层增加过滤器，`stock`表status字段增加过滤枚举，自动排除：

```
非沪深主板（创业板/科创板/北交所）
ST / *ST
退市整理期
停牌
流动性异常（例如近5日日均成交额低于阈值，建议5000万，可配置）
```
被排除股票禁止进入核心池/观察池，即使涨停也不参与主线/龙头评分计算。

### A7：交易制度校验模块

新增模块，开仓/卖出前依次校验：

```
1. 交易日判断（非节假日、非周末）
2. 交易时间判断：
   9:15–9:25  集合竞价（只观察，不生成BUY候选）
   9:30–11:30 / 13:00–15:00  盘中（唯一允许生成BUY候选的时段）
   14:57–15:00  收盘集合竞价（仅监控，不新开仓）
3. 停牌状态检查
4. 涨跌停状态检查（涨停不可买/跌停不可卖，需实时判断"一字板"无法成交的情形）
5. 最小交易单位检查（100股整数倍，卖出允许零股）
6. T+1可卖数量检查（当日买入部分不计入可卖数量）
7. 交易费用估算（佣金+印花税(卖出)+过户费，计入实际盈亏）
8. 除权除息调整（持仓成本价自动重算，避免除权日误判止损触发）
```

### A9：手机端详细规范

软件规格书第七章直接**引用并整体纳入**交易规则v0.5第十三章（13.1–13.10节）的全部内容，不要求重写，只需在软件规格书中加一句：

> "首页六大模块的具体展示逻辑、优先级顺序、字段说明，以交易规则v0.5第十三章为准，本规格书不重复定义。"

### A10：止损比例明确定义

软件规格书第4.1节修正为：

```
止损幅度 = |买入价格 - 止损价格| ÷ 买入价格
预计最大亏损 = 持仓金额 × 止损幅度
账户风险比例 = 预计最大亏损 ÷ 账户总资金
```

### B3：龙头模式切换矩阵（重建）

新增"龙头状态"自动计算字段（基于涨跌幅、量能变化率、连板高度变化）：

```
主动攻击：涨停或大幅上涨 + 量能温和放大 + 连板高度提升/维持
分歧    ：炸板或大幅震荡 + 换手率激增
加速    ：连续涨停 + 短期涨幅陡峭（通常伴随情绪周期=高潮）
破位    ：跌破关键技术位（5日线/前低） + 资金净流出
```

情绪周期 × 龙头状态 → 建议交易模式：

| 情绪周期 | 龙头状态 | 建议交易模式 |
| --- | --- | --- |
| 启动 | 主动攻击 | 强势跟随 |
| 启动/修复 | 分歧 | 分歧低吸（前提：龙头逻辑未破坏） |
| 分歧 | 加速 | 不追，仅HOLD |
| 分歧/修复 | 破位 | 弱转强观察（等待企稳，不立即买入） |
| 高潮 | 加速 | 不追高，仅REDUCE |
| 退潮 | 任意 | EXIT优先，禁止新开仓 |
| 冰点 | 破位 | 观察，不操作 |

### B4：情绪匹配度评分标准

| 情绪周期 | 评分范围 |
| --- | --- |
| 启动 | 12–15 |
| 修复 | 8–12 |
| 分歧 | 5–8 |
| 高潮 | 5–10 |
| 退潮 | 0–5 |
| 冰点 | 0–3 |

### B5：情绪灯号升级规则

```
红灯 → 橙灯：龙头止跌、杀跌减缓
橙灯 → 黄灯：龙头出现承接、涨停回升
黄灯 → 绿灯：主线确认、龙头主动攻击
```

**补充建议（防止灯号抖动）**：升级需连续2个交易日数据确认后才生效，降级可以单日触发立即生效（风险控制"宁可错杀不可放过"的不对称原则）。

## 三、低优先级问题修订方案（开发中处理即可）

**A8** — AI输出字段拆分：
```json
{
  "判断类型": "辅助分析",
  "市场环境": "震荡",
  "情绪周期": "分歧",
  "情绪灯号": "黄灯",
  "核心逻辑": "资金仍集中",
  "风险提示": "高位股波动增加",
  "建议状态": "观察"
}
```

**B6** — 单日风险公式加括号：
```
当日总风险 = (已有持仓预计亏损 + 计划交易预计亏损) ÷ 账户资金
```

**B8** — 交易评分标准重建（100分制，写入`decision_score`字段）：
```
市场判断20（买入时最终等级是否为L2以上）
+ 主线判断20（是否属于当日核心主线）
+ 个股选择20（龙头评分是否≥70）
+ 买点质量20（买点四要素是否完整、是否符合对应交易模式）
+ 执行纪律20（是否触发is_violation、是否按计划止损/止盈执行）
```

**B9** — 高潮特征定义：情绪周期=高潮时即视为高潮特征成立，不做二次主观判断。

**B10** — T+1量化缓冲：
```
T+1调整后风险估算 = 预计最大亏损 × 1.2 ÷ 账户资金
```
（1.2为隔夜风险缓冲系数，仅用于仓位决策提前预警，不改变实际止损价位）
